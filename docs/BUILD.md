# Build instructions

## Requirements

- **Node.js 20+** and npm. Nothing else is needed — VegaAM has **no runtime
  dependencies** and every source file is bundled by esbuild.
- A C++ toolchain is **not** required: no native module is compiled.
- Linux packaging additionally needs `rpm` (for the rpm target) and the usual
  electron-builder host packages.

```sh
npm ci
npm run typecheck
npm test
npm run build
```

The bundle contains the main process, the three preloads, the four VegaAM renderers
and the independent VegaAM icons generated by `scripts/make-icons.mjs`. There is no
server component and no external service dependency.

## Packaging per platform

| Platform | Command | Runs on |
| :--- | :--- | :--- |
| Windows | `npm run dist -- --win --x64` (or `--arm64`) | Windows |
| macOS | `npm run dist -- --mac` | **macOS only** (DMG + ZIP) |
| Linux | `npm run dist -- --linux` | **Linux only** (AppImage, deb, rpm) |

- **Windows:** the NSIS installer, `VegaAM-<version>-x64.exe` or
  `VegaAM-<version>-arm64.exe`. To build one architecture on its own, use the
  isolated configs:
  `node build/electron-builder.cjs --config build/electron-builder.x64.yml` or
  `--config build/electron-builder.arm64.yml`.
- **macOS:** DMG and ZIP for `x64` and `arm64`. Signing and notarization need your
  own Developer ID identity and Apple credentials (`CSC_LINK`, `CSC_KEY_PASSWORD`,
  `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`). Without them the
  build succeeds but the artifact is unsigned.
- **Linux:** AppImage for `x64` and `arm64`, plus `deb` and `rpm` for `x64`.
  Dependencies for the deb package: `libgtk-3-0`, `libnotify4`, `libnss3`,
  `libxss1`, `libxtst6`, `xdg-utils`, `libatspi2.0-0`, `libsecret-1-0`.
- **Unpacked development build:** `npm run pack`.

The output directory is `release/` (the isolated arm64 config writes to
`release-arm64/`). Both are git-ignored.

## Build toolchain notes

- **No production dependencies.** Everything is esbuild-bundled into `dist/`, and
  `package.json` declares `"dependencies": {}` explicitly so `electron-builder` can
  resolve the dependency tree without a globally installed npm.
- **`build/electron-builder.cjs`** wraps the `electron-builder` CLI and sets
  `process.defaultApp = true`. Under `ELECTRON_RUN_AS_NODE`, yargs' `hideBin()`
  otherwise assumes a bundled Electron app and mis-slices `process.argv`, making the
  CLI reject its own script path as an unknown argument. The wrapper also sets
  `process.noAsar = true` so Electron's ASAR path interception does not break
  electron-builder's copy of `resources/default_app.asar`.
- **`build/toolchain/npm.cmd` / `npm-shim.cjs`** — an optional `npm` stand-in for
  Windows build machines that have no Node/npm installed. It reports the truthful
  (empty) production dependency tree. CI has a real npm and does not use it.
- **`scripts/make-icons.mjs`** renders the application, installer, taskbar and tray
  icons deterministically from the V-star geometry in
  `assets/branding/vegaam-mark.svg` — no binary asset has to be trusted from the
  repository. `scripts/verify-icons.mjs` verifies the result.

## Last.fm credentials at build time (optional)

The open-source build has **no built-in Last.fm key pair**; users enter their own in
Settings → Accounts. If you build a private release and want your own pair baked in:

```sh
cp .env.example .env.local      # fill in VEGAAM_LASTFM_API_KEY / _SECRET
npm run build                   # development build
npm run dist                    # release build (refuses a revoked secret)
```

The values are injected into the **main-process bundle only** and are never
committed, printed or logged. A release build *without* credentials is valid.

## Reusing a local Electron distribution

When GitHub downloads are unavailable, electron-builder can reuse a matching
installed runtime:

```sh
node node_modules/electron-builder/out/cli/cli.js --config.electronDist=node_modules/electron/dist --win nsis --x64
```

## UI and live acceptance runs

These require a **real, signed-in SiriusXM session** on the local machine and
produce screenshots plus machine-readable telemetry. They are development tools,
not part of the shipped product, and they write into `artifacts/` (git-ignored).

- `--qa-3-2` (`npm run qa:3.2`): the full live acceptance suite. It starts live
  playback, switches through all **14 themes** (9 dark + 5 light), opens every drawer
  tab (**Appearance, Activity & History, Scrobbling Rules, Accounts, Companions &
  Desktop, About & Help**), exercises a real mouse click on a theme card, keyboard
  Tab navigation, Escape, focus return and scrolling, resizes to `900×600`,
  `1280×860` and maximized, and verifies the auth/billing route guard. It asserts
  `BrowserWindow.getAllWindows().length === 1` and `executeJavaScriptCount === 0` at
  every step. Set `VEGAAM_QA_OUTPUT` to override the output directory (default
  `artifacts/v3.2-acceptance`).
- `--verify-official-first` / `--smoke` (`npm run smoke`): verifies that the main
  window loads `https://www.siriusxm.com/player` directly in the top-level
  `BrowserWindow`, `executeJavaScriptCount === 0` and `insertCSSCount === 0`, then
  captures the main window and the VegaAM companion windows, asserting
  `horizontalOverflow: false` and `audioVideoElements: 0` across all secondary
  windows. Set `VEGAAM_SMOKE_OUTPUT` to override the output directory (default
  `artifacts/v3-acceptance`).
- `--qa-threshold` (`npm run qa:threshold`): measures the adaptive scrobble
  threshold against a live broadcast.
- `--live-probe` (`npm run live-probe`): exercises live playback across extended
  radio listening and real channel transitions using only native window input and
  the read-only `navigator.mediaSession` preload bridge.

## Documentation screenshots

```sh
npm run screenshots
```

`scripts/capture-screenshots.mjs` renders VegaAM's own interface — the integrated
studio drawer, the Skinned Companion and the Compact mini-player — with **mocked
state** and writes the images to `assets/screenshots/`. It never loads
`siriusxm.com`, never opens a network connection and never reads a user profile, so
the README images can be regenerated on any machine **without** a SiriusXM account.

It uses the *real* production renderer bundles and the *real* theme palettes and
skins, so the screenshots cannot drift away from the product.

## Distribution verification

Check the executable's `ProductName`/`FileDescription` (`VegaAM`), the version, the
`app.asar` contents, the output SHA-256, and the packaged `--qa-3-2` checks
(`release/win-unpacked/VegaAM.exe --qa-3-2`). Artifacts are **unsigned** unless a
signing identity was supplied.
